# 系统级元素选择器设计文档

## 概述

设计一个桌面级的UI元素选择器，允许用户在DeeChat中点击"选择元素"按钮后，直接选择系统中任意正在运行的应用程序中的UI元素，并将元素信息自动附加到AI对话中。

## 核心理念

**让AI助手成为桌面环境的原生参与者，而不是一个独立的聊天工具。**

用户可以直接与正在使用的任何应用程序进行"对话"，AI能够理解用户的工作上下文，并提供基于当前操作环境的智能建议。

## 用户体验设计

### 操作流程
```
1. 用户在DeeChat对话界面点击"选择元素"按钮
2. DeeChat主窗口自动最小化或变为半透明
3. 整个桌面覆盖一层透明的选择界面
4. 鼠标移动时，实时高亮当前指向的UI元素
5. 显示元素信息提示（应用名、元素类型、内容预览）
6. 用户点击选择目标元素
7. 自动返回DeeChat，显示捕获的元素信息
8. AI基于元素信息提供上下文相关的建议
```

### 视觉设计

#### 选择模式界面
- **全屏透明覆盖层**: 保持桌面可见，用户能看到所有应用
- **实时元素高亮**: 鼠标悬停时用蓝色边框高亮元素
- **信息提示框**: 跟随鼠标显示元素基本信息
- **取消按钮**: ESC键或右上角关闭按钮

#### 高亮效果
```css
.element-highlight {
  border: 2px solid #007AFF;
  background: rgba(0, 122, 255, 0.1);
  border-radius: 4px;
  box-shadow: 0 0 10px rgba(0, 122, 255, 0.5);
  animation: pulse 1.5s infinite;
}
```

#### 信息提示框
```
┌─────────────────────┐
│ 📱 Microsoft Excel  │
│ 📊 表格单元格        │
│ "2024年销售数据"     │
└─────────────────────┘
```

### 交互细节

#### 多选模式
- **Cmd/Ctrl + 点击**: 多选元素
- **拖拽框选**: 选择区域内的多个元素
- **选择计数器**: 显示已选择的元素数量

#### 选择反馈
- **成功动画**: 选中时的视觉确认
- **音效反馈**: 轻微的选择音效
- **返回动画**: 平滑回到DeeChat界面

## 功能特性

### 1. 元素信息获取

#### 基础信息
- **元素类型**: 按钮、文本框、图片、表格等
- **文本内容**: 可见文本或OCR识别文本
- **位置边界**: 精确的像素位置和尺寸
- **可访问性信息**: 角色、描述、标签等

#### 应用上下文
- **应用名称**: 元素所属的应用程序
- **窗口标题**: 当前窗口的标题
- **文档信息**: 文件名、路径等（如果可获取）
- **操作系统信息**: 平台、版本等

#### 视觉信息
- **元素截图**: 高清的元素区域截图
- **完整截图**: 可选的全屏截图作为上下文
- **OCR文本**: 图像中的文字识别结果

#### 结构化数据
- **表格数据**: 如果是表格，提取行列数据
- **列表项目**: 如果是列表，提取所有项目
- **表单字段**: 表单中的字段名和值
- **层级关系**: UI元素的父子关系

### 2. 智能分析增强

#### AI内容理解
- **语义分析**: 理解元素的功能和用途
- **上下文推理**: 基于应用和工作流推断用户意图
- **数据分析**: 对表格、图表等数据进行分析
- **设计分析**: 对UI元素的设计进行评估

#### 智能建议
- **操作建议**: 基于元素类型推荐可能的操作
- **优化建议**: 对设计、代码、数据的改进建议
- **工作流建议**: 基于当前工作推荐下一步操作
- **学习建议**: 相关知识点和技能推荐

### 3. 跨应用能力

#### 支持应用类型
- **办公软件**: Excel, Word, PowerPoint, Numbers, Pages
- **设计工具**: Figma, Sketch, Adobe Creative Suite
- **开发工具**: VS Code, Xcode, Terminal, Git客户端
- **浏览器**: Chrome, Safari, Firefox, Edge
- **通讯工具**: Slack, Teams, Discord, 邮件客户端
- **系统应用**: Finder, 系统设置, 计算器等

#### 适配策略
- **深度集成**: 重点应用的API级别集成
- **无障碍支持**: 基于系统无障碍API的通用支持
- **智能降级**: 不支持的应用使用截图+OCR方案

## 技术架构

### 系统级别
```
┌─────────────────┐
│   DeeChat UI    │ 用户界面层
├─────────────────┤
│ Element Capture │ 元素捕获层
├─────────────────┤
│ Platform Bridge │ 平台适配层
├─────────────────┤
│   MCP Tools     │ MCP工具集成
├─────────────────┤
│  OS APIs        │ 操作系统API
└─────────────────┘
```

### 关键组件

#### 1. DesktopElementSelector
- 全屏透明窗口管理
- 实时鼠标跟踪
- 元素检测和高亮
- 用户交互处理

#### 2. CrossPlatformAdapter
- macOS实现（基于Accessibility API）
- Windows实现（基于UI Automation）
- Linux实现（基于AT-SPI）
- 统一接口封装

#### 3. ElementAnalyzer
- 基础信息提取
- 结构化数据解析
- AI增强分析
- 上下文推理

#### 4. MCPIntegration
- macOS MCP工具集成
- Windows MCP工具集成
- 工具能力协调
- 错误处理和降级

### 数据流程
```
用户点击按钮
    ↓
启动选择模式
    ↓
实时元素检测 → 高亮显示
    ↓
用户选择元素
    ↓
MCP工具获取详细信息
    ↓
AI分析和增强
    ↓
集成到对话上下文
    ↓
显示给用户并提供建议
```

## 竞争优势

### 与现有方案对比

#### 传统截图分享
- **传统方式**: 截图 → 上传 → OCR识别 → 分析
- **DeeChat方式**: 点击选择 → 即时分析 → 智能建议

#### 现有AI工具
- **ChatGPT Desktop**: 独立聊天，无系统集成
- **Claude Desktop**: 基础MCP，需手动配置
- **Copilot**: 主要限于微软生态

#### DeeChat独特价值
- **无缝集成**: 任意应用的原生交互
- **智能降级**: 总有可用的方案
- **上下文理解**: 深度理解用户工作流
- **开箱即用**: 无需复杂配置

### 核心差异化
1. **系统级集成** vs 应用级工具
2. **主动上下文感知** vs 被动信息处理
3. **工作流原生支持** vs 独立功能模块
4. **智能适配** vs 固定功能
