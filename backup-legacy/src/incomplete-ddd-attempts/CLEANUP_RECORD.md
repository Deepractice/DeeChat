### **简洁的Electron架构**
```
src/
├── main/      # Electron主进程
│   ├── services/   # 业务服务（ChatService等）
│   ├── core/      # 核心服务管理
│   └── ipc/       # IPC处理
├── renderer/  # React前端UI
├── preload/   # IPC桥接API
└── shared/    # 共享类型和工具
```

## 🎯 **架构决策**

### **选择简洁而非复杂**
- ✅ 遵循Electron的天然架构
- ✅ 业务逻辑集中在main进程services
- ✅ UI层专注于展示和交互
- ✅ 最小化抽象层次

### **实用主义原则**
- 先让功能工作，再考虑完美架构
- 避免过度设计和预先优化
- 保持代码可读性和可维护性
- 支持快速迭代和功能开发

## 📝 **经验总结**

1. **架构要适合团队规模** - 独立开发/小团队不需要复杂的企业级架构
2. **渐进式演化** - 架构应该随着需求自然演化，而非一开始就设计完美
3. **技术为业务服务** - 选择最能快速交付价值的技术方案
4. **可工作 > 完美** - 工作的简单代码胜过不工作的完美架构
