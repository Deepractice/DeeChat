🌐 AI应用的本质：API请求机制

现代AI应用如何与大模型通信

📡 HTTP请求基础

核心流程：
1️⃣ 构建HTTP POST请求
2️⃣ 设置Authorization Header
3️⃣ 发送JSON格式消息
4️⃣ 处理响应或Stream

端点示例：
• OpenAI: /v1/chat/completions
• Claude: /v1/messages

💬 消息格式标准

标准消息结构：
role - 角色类型
content - 消息内容
name - 工具名(可选)

角色类型：
• system - 系统提示
• user - 用户输入
• assistant - AI回复
• tool - 工具结果

⚡ 流式响应(SSE)

Server-Sent Events：
设置 stream: true
监听 data: 事件
解析JSON chunk

优势：
✅ 实时响应体验
✅ 减少用户等待时间
✅ 支持打字机效果
✅ 可中断长对话

🔧 工具调用(Function Calling)

现代AI的核心能力：
1. 定义工具Schema
2. AI决策调用工具
3. 执行工具获取结果
4. 返回结果给AI

应用场景：
🔍 搜索、📊 数据查询
🌐 API调用、📁 文件操作

📋 架构设计总结

DeeChat包架构的设计亮点

🎯 设计原则

✅ 单一职责原则 - 每个包职责清晰
✅ 依赖注入设计 - 降低模块耦合
✅ 接口隔离原则 - 最小化接口依赖
✅ 开闭原则 - 支持扩展不修改

🏗️ 架构优势

⚡ Monorepo统一管理
🔧 TypeScript类型安全
📦 模块化可复用设计
🧪 易于单元测试

🚀 技术特色

🎨 策略模式 - token-calculator
🏭 工厂模式 - ai-chat适配器
📋 适配器模式 - database层
💉 依赖注入 - 全模块支持

🔮 扩展能力

🌐 支持新AI服务商接入
🗄️ 支持多种数据库后端
🔌 支持多种MCP传输协议
📈 支持新token计算策略
