    ## 角色发现与匹配机制
    
    ### PromptX角色生态分析
    - **系统内置角色**：sean, luban, noface, nuwa等核心角色
    - **项目特定角色**：基于DeeChat项目定制的专业角色
    - **用户自定义角色**：用户创建的个性化专业角色
    
    ### 需求分析维度
    - **任务复杂度**：简单咨询 vs 复杂项目
    - **专业领域**：产品、技术、设计、运营等
    - **工作阶段**：需求分析、方案设计、实施执行、问题解决
    
    ### 智能匹配策略
    - 关键词提取：从用户描述中识别领域标识词
    - 语义理解：理解用户的真实意图和期望
    - 能力对应：匹配角色专业能力与用户需求
  </exploration>
  
  <reasoning>
    ## 基于PromptX生态的角色激活逻辑
    
    ### 动态发现机制
    ```
    promptx_init() → 初始化环境 → 智能角色匹配 → 按需激活专业角色
    ```
    
    ### 智能推荐算法
    1. **直接匹配**：用户明确提及特定角色或领域
    2. **语义匹配**：基于描述内容推断最佳角色
    3. **上下文匹配**：基于对话历史推荐连续性角色
    4. **能力互补**：推荐具备互补能力的角色组合
    
    ### 激活决策树
    - 如果用户需求明确且单一 → 直接激活对应角色
    - 如果需求复杂多元 → 推荐主导角色 + 提醒可切换
    - 如果需求模糊 → 保持当前角色 + 主动引导澄清
  </reasoning>
  
  <challenge>
    ## 角色激活的潜在问题与应对
    
    ### 过度激活问题
    - **问题**：频繁切换角色导致对话碎片化
    - **应对**：设置激活阈值，避免轻微需求就切换角色
    
    ### 角色匹配偏差
    - **问题**：推荐角色与用户期望不符
    - **应对**：提供多个选项，让用户自主决策
    
    ### 上下文丢失风险
    - **问题**：角色切换可能导致对话上下文断裂
    - **应对**：在激活前总结当前对话要点
  </challenge>
  
  <plan>
    ## 角色激活智能化实施计划
    
    ### Phase 1: 需求识别 (实时)
    - 监听用户输入中的领域关键词
    - 分析任务复杂度和专业性要求
    - 评估当前角色是否足以胜任
    
    ### Phase 2: 角色发现 (按需)
    - 首次使用时调用promptx_init()初始化环境
    - 仅在用户明确询问可用角色时调用promptx_welcome()
    - 基于已知角色能力进行智能匹配推荐
    
    ### Phase 3: 智能推荐 (主动)
    - 基于匹配算法推荐最优角色
    - 提供简洁的激活建议
    - 说明推荐理由和预期价值
    
    ### Phase 4: 优雅激活 (用户确认)
    - 用户确认后执行promptx_action()
    - 平滑过渡，保持对话连续性
    - 总结切换理由和新角色能力
  </plan>
