# DeeChat 包依赖注入重构方案

## 背景问题

当前 `@deepracticex/ai-config` 和 `@deepracticex/conversation-storage` 包直接依赖 `better-sqlite3`，导致以下问题：

1. **重复依赖**：多个包都包含相同的原生模块依赖
2. **版本冲突**：不同 Node.js 版本编译的原生模块不兼容
3. **包体积大**：每个包都携带完整的 SQLite 依赖
4. **编译复杂**：需要为每个包单独编译原生模块
5. **环境限制**：包与特定的 Node.js 版本和平台强耦合

## 重构目标

- 📦 **轻量化包**：移除原生依赖，专注业务逻辑
- 🔧 **灵活配置**：支持多种数据库实现
- 🧪 **易于测试**：支持依赖注入和 Mock
- 🌍 **环境适配**：适应不同运行环境
- 📈 **可扩展性**：便于支持新的数据库类型

## 重构方案

### 1. 定义数据库适配器接口

```typescript
// packages/database-adapter/src/interfaces.ts
export interface DatabaseAdapter {
  // 连接管理
  connect(): Promise<void>;
  close(): Promise<void>;

  // 查询操作
  prepare(sql: string): PreparedStatement;
  exec(sql: string): void;
  transaction<T>(fn: () => T): T;

  // 状态检查
  isConnected(): boolean;
}

export interface PreparedStatement {
  run(...params: any[]): { changes: number; lastInsertRowid: number };
  get(...params: any[]): any;
  all(...params: any[]): any[];
  finalize(): void;
}
```

### 2. Better-SQLite3 适配器实现

```typescript
// packages/database-adapter/src/better-sqlite3-adapter.ts
import Database from 'better-sqlite3';
import { DatabaseAdapter, PreparedStatement } from './interfaces.js';

export class BetterSQLite3Adapter implements DatabaseAdapter {
  private db: Database.Database | null = null;

  constructor(private dbPath: string, private options?: Database.Options) {}

  async connect(): Promise<void> {
    this.db = new Database(this.dbPath, this.options);
  }

  async close(): Promise<void> {
    if (this.db) {
      this.db.close();
      this.db = null;
    }
  }

  prepare(sql: string): PreparedStatement {
    if (!this.db) throw new Error('Database not connected');
    const stmt = this.db.prepare(sql);

    return {
      run: (...params) => stmt.run(...params),
      get: (...params) => stmt.get(...params),
      all: (...params) => stmt.all(...params),
      finalize: () => stmt.finalize(),
    };
  }

  exec(sql: string): void {
    if (!this.db) throw new Error('Database not connected');
    this.db.exec(sql);
  }

  transaction<T>(fn: () => T): T {
    if (!this.db) throw new Error('Database not connected');
    return this.db.transaction(fn)();
  }

  isConnected(): boolean {
    return this.db !== null;
  }
}
```

### 3. AI Config 包重构

```typescript
// packages/ai-config/src/index.ts
import { DatabaseAdapter } from '@deepracticex/database-adapter';

export interface AIConfigOptions {
  database: DatabaseAdapter;  // 注入数据库适配器
  tablePrefix?: string;
  autoMigrate?: boolean;
}

export class AIConfigManager {
  private database: DatabaseAdapter;
  private tablePrefix: string;

  constructor(options: AIConfigOptions) {
    this.database = options.database;
    this.tablePrefix = options.tablePrefix || '';

    if (options.autoMigrate !== false) {
      this.migrate();
    }
  }

  async initialize(): Promise<void> {
    if (!this.database.isConnected()) {
      await this.database.connect();
    }
  }

  private migrate(): void {
    // 使用注入的数据库适配器执行迁移
    const sql = `CREATE TABLE IF NOT EXISTS ${this.tablePrefix}ai_configs (...)`;
    this.database.exec(sql);
  }

  // 其他业务方法...
}
```

### 5. 使用方式

#### 在 DeeChat 应用中使用
```typescript
// app/main/domains/AIConfigurationDomain.ts
import Database from 'better-sqlite3';
import { BetterSQLite3Adapter } from '@deepracticex/database-adapter';
import { AIConfigManager } from '@deepracticex/ai-config';

// 创建数据库适配器
const dbAdapter = new BetterSQLite3Adapter(dbPath, {
  verbose: console.log
});

// 注入到业务包中
const aiConfigManager = new AIConfigManager({
  database: dbAdapter,
  tablePrefix: 'deechat_',
  autoMigrate: true
});

await aiConfigManager.initialize();
```

## 收益评估

### 包体积对比
- **重构前**: ai-config (2.3MB) + conversation-storage (2.1MB) = 4.4MB
- **重构后**: ai-config (0.2MB) + conversation-storage (0.2MB) + database-adapter (0.1MB) = 0.5MB

### 依赖管理
- **重构前**: 每个包独立编译 better-sqlite3
- **重构后**: 应用层统一管理一个 better-sqlite3 实例

### 灵活性提升
- 支持多种数据库后端
- 便于单元测试
- 环境适配性更好

## 风险评估

### 破坏性变更
- 现有用户需要更新初始化代码
- 需要版本迁移指南

### 复杂度增加
- 用户需要理解依赖注入概念
- 初始化步骤略有增加

### 缓解措施
- 提供详细的迁移文档
- 保留向后兼容的便捷构造函数
- 提供完整的示例代码

## 总结

通过依赖注入重构，我们可以显著提升包的通用性、可测试性和可维护性，同时解决当前的原生依赖编译问题。这是一个符合现代 npm 包最佳实践的重构方案。
