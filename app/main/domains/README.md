# 🏗️ Domains 架构说明

## 📖 总览
本目录采用 **DDD (领域驱动设计)** 架构，每个领域都有清晰的职责分工。

## 🏛️ 聚合根 (Aggregate Roots)
> 聚合根是领域的统一入口，负责协调内部组件

| 文件 | 职责 | 内部组件目录 |
|------|------|-------------|
| `ConversationDomain.ts` | 🗣️ 对话功能协调 | `./conversation/` |
| `McpDomain.ts` | 🔧 MCP工具管理 | 无 (单体实现) |

## 📁 领域内部结构
```
conversation/           # 🗣️ 对话领域实现
├── types/             # 📋 TypeScript 类型定义
├── services/          # ⚙️ 业务逻辑服务
├── repositories/      # 🗄️ 数据访问层
└── adapters/          # 🔌 外部接口适配
```

## 🔄 工作流程
1. **应用启动** → 初始化各个聚合根
2. **IPC请求** → 聚合根分发给对应服务
3. **业务处理** → 服务层处理具体逻辑
4. **数据操作** → 仓储层负责数据存取

## 🎯 设计原则
- **单一职责**: 每个文件只负责一个明确功能
- **依赖清晰**: 聚合根协调，服务层专业分工
- **易于测试**: 模块化设计，便于单元测试
- **便于扩展**: 新功能只需添加对应服务
